# Integrated Intelligence Agent (IIA)

Unified AI study and productivity assistant with chat, PDF-grounded answers, quiz generation, and a versioned developer API.

**Production safety:** this repository is separate from the live Smart Quiz website. Changes in this branch are not deployed automatically by this work. Do not change production DNS or deploy until CI and deployment checks pass.

## IIA Developer API v1

The API is served by the IIA backend; it is a project-owned interface, while the initial AI responses are generated by the configured Gemini provider. A self-hosted model can be evaluated later behind the same interface.

### API endpoints

| Method | Endpoint | Authentication | Purpose |
| --- | --- | --- | --- |
| GET | `/api/v1/health` | None | Health check |
| GET | `/api/v1/docs` | None | Machine-readable API overview |
| POST | `/api/developer/keys` | User JWT | Create an API key |
| GET | `/api/developer/keys` | User JWT | List your keys (secret values are never returned) |
| DELETE | `/api/developer/keys/:id` | User JWT | Revoke one of your keys |
| POST | `/api/v1/chat` | IIA API key | Ask a question |
| GET | `/api/v1/quizzes` | IIA API key | List quizzes visible to the key owner |

### Create an API key

First sign in to IIA and obtain the existing user bearer token. Then create a named key:

```bash
curl -X POST "https://YOUR-IIA-HOST/api/developer/keys" \
  -H "Authorization: Bearer YOUR_USER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"My integration"}'
```

The response contains `key` once. Copy it to a secure secret store; IIA persists only its SHA-256 hash. The full secret cannot be retrieved later. If it is lost, create a replacement and revoke the old key.

### Ask IIA a question

```bash
curl -X POST "https://YOUR-IIA-HOST/api/v1/chat" \
  -H "X-IIA-API-Key: iia_live_YOUR_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{"message":"Explain the difference between a beam and a column."}'
```

For multi-step analysis, set `"taskMode": true`. The normal chat response includes an `answer`, `model`, and `provider`; multi-step mode also includes task steps. PDF-based API questions currently use the website's authenticated upload workflow rather than accepting arbitrary file URLs.

### List quizzes

```bash
curl "https://YOUR-IIA-HOST/api/v1/quizzes" \
  -H "X-IIA-API-Key: iia_live_YOUR_SECRET_KEY"
```

### Security and limits

- Send API keys only in the `X-IIA-API-Key` header over HTTPS. Never put keys in URLs, browser source code, public repositories, or client-side apps.
- Keys are scoped to the account that created them; revocation takes effect on the next request.
- Stored API key material contains only a SHA-256 hash and a short prefix, not the full secret.
- The versioned API has a default limit of 60 requests per 15 minutes per client IP. Developer key creation is limited to 10 per hour per client IP, with at most 10 active keys per account.
- Chat uses the server's `GEMINI_API_KEY`. Never expose that provider key to API consumers.
- API key records are persisted alongside the current JSON store. For production-scale multi-instance usage, migrate to a transactional database and shared rate-limit storage before broad public release.
- Website search is intentionally not part of IIA v1.

## Configuration

Set secrets on the server environment, not in source control. Production requires a unique `JWT_SECRET` of at least 32 bytes. Chat and AI quiz generation require `GEMINI_API_KEY`; `GEMINI_MODEL` may override the default model.

## Validation

CI runs backend build/tests, frontend build, Docker build, and API smoke tests on pull requests. Do not merge or deploy unless those checks pass.
